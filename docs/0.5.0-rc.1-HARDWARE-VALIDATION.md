Observed fans after startup recovery:

```text
Fan 0: 1836 / 5616 RPM
Fan 1: 1709 / 5200 RPM
```

Result: **PASS**.

This verified that:

- BCPC fan ownership/recovery context survived forced process termination,
- startup recovery returned owned fans to Apple Auto,
- Apple Auto was verified before ownership cleanup,
- the processor remained intentionally in the Gaming state,
- the original processor Restore snapshot survived the crash and fan recovery.

## Gate HW-D — fan-only resume and snapshot preservation

Starting from the valid split state:

```text
CPU:      95 / 95
Boost:    0 / 0
Snapshot: original processor Restore snapshot still available
Fans:     Apple Auto
```

Gaming Optimised was activated again.

The operator confirmed that fan-only resume returned the fans to the expected Manual / Maximum Safe RPM state without replacing the original processor Restore snapshot.

A subsequent explicit `Restore Original Settings` returned the reference machine to its original processor state and Apple Auto.

Result: **PASS**.

This confirms the critical invariant that fan-only resume does not rewrite the processor profile or replace the Restore snapshot created before the original Gaming transaction.

## Safety boundaries preserved

No validation step changed the production safety boundary:

- targets came from fresh live `F{i}Mx` values,
- no arbitrary SMC key was written,
- no minimum-RPM write was used,
- no user-defined RPM was used,
- no `FS!` / T1 `fpe2` write was used,
- no CPU undervolting or MSR write was used,
- no firmware or display timing was changed,
- no third-party driver was bundled or redistributed,
- native experimental `BootCampSmc` was not used for production control.

## Release interpretation

This evidence is sufficient to treat the `MacBookPro16,1` Phase B path as physically validated end-to-end and to prepare `0.5.0-rc.1` for broader controlled testing.

It is **not** sufficient to promote the project to `1.0`, to declare all T2 models physically validated, or to enable T1 fan writes.

For another machine, the next safe sequence remains read-only capability capture first, then controlled write/read-back/Apple Auto Restore only if the live family fingerprint passes.
