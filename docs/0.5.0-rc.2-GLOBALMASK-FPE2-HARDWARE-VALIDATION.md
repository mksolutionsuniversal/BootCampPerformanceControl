# 0.5.0-rc.2 GlobalMaskFpe2 Hardware Validation Record

## Status

**PASS — one-fan `GlobalMaskFpe2` physical write/readback/Apple Auto round trip completed on `MacBookPro12,1`.**

This record documents the first BCPC-owned physical write qualification of the bounded `GlobalMaskFpe2` fan-control family.

It does **not** establish generic T1 support, two-fan `GlobalMaskFpe2` physical qualification, or physical write qualification of the native `BootCampSmc` research driver.

## Controlled physical transaction

Only three SMC write attempts were issued:

```text
WRITE #1: FS!  0001
READBACK: FS! raw=0001

READBACK: F0Mx raw=60DC
WRITE #2: F0Tg 60DC
READBACK: F0Tg raw=60DC

WRITE #3: FS!  0000
READBACK: FS! raw=0000
Emergency/final Apple Auto readback: VERIFIED 0000
```

The target payload was not decoded and re-encoded for the physical write. The exact fresh two-byte `F0Mx` payload `60DC` was copied to `F0Tg` and verified byte-for-byte.

The brief audible fan ramp observed by the tester was consistent with the temporary `F0Tg = 6199 RPM` command, but this record does not claim that `F0Ac` reached 6199 RPM before Apple Auto was restored. The transaction intentionally kept manual ownership extremely short.

## Final state

The final capability probe after `FS! = 0000` reported:

```text
Model: MacBookPro12,1
Protocol: Mmio (1)
Family: GlobalMaskFpe2
Read supported: True
Hardware safety gate: True
FNum: raw=01
FS! : raw=0000
F0Mx: raw=60DC, decodedRpm=6199
F0Tg: raw=60DC, decodedRpm=6199
F0Md observation: ConfirmedAbsent
Capability failures/warnings: none
```

`F0Tg` remaining at the maximum payload after return to Auto is not treated as manual ownership. For this capability family, `FS! ` is the mode authority, and final `FS! = 0000` was explicitly verified.

## What is now physically qualified

For the observed one-fan `GlobalMaskFpe2` family on `MacBookPro12,1`, the project has physical evidence that:

- the exact family fingerprint is readable and stable,
- `fpe2` uses the confirmed unsigned big-endian `raw / 4` encoding,
- `FS! 0000 -> 0001` enters the bounded one-fan manual state,
- `FS! 0001` readback is exact,
- fresh exact `F0Mx` bytes can be written to `F0Tg`,
- `F0Tg` readback matches those exact bytes,
- `FS! 0001 -> 0000` returns control to Apple Auto,
- final `FS! 0000` readback is exact,
- final capability probing remains healthy after the round trip.

This is sufficient to change the one-fan `GlobalMaskFpe2` status from read-only physical evidence to **physically write-qualified**.

## Explicit non-claims

This PASS does not establish any of the following:

- physical qualification of the two-fan `GlobalMaskFpe2` takeover mask `0003`,
- generic physical qualification of all T1 Macs,
- generic physical qualification of every Intel Mac exposing `fpe2`,
- model-based writer selection,
- permission to broaden the public write surface beyond Apple Auto and Maximum Safe RPM,
- physical write qualification of the native `BootCampSmc` research driver,
- permission to redistribute CrystalIdea/Macs Fan Control proprietary binaries.

Two-fan `GlobalMaskFpe2` remains bounded in software from existing mask evidence but is not BCPC-owned physically write-qualified until a suitable physical two-fan machine is tested.

## Release implication

The runtime writer remains capability-driven. `MacBookPro12,1` is validation evidence, not a production whitelist entry.

PR #52 merged the bounded production `GlobalMaskFpe2` family, and `v0.5.0-rc.2` was subsequently published as a GitHub pre-release. This record remains the physical one-fan qualification checkpoint for that family, while unknown fingerprints and unproven topologies continue to fail closed. The dedicated qualifier source is preserved by `evidence/global-mask-fpe2-one-fan-pass-2026-09-08`.
